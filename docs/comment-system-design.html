    3. Status

    ใช้สี + ชื่อเต็มเสมอ (ไม่ใช้สีอย่างเดียว) · Complete เก็บถาวรจนกว่าจะมีคนลบเอง · หมุดของ Complete ซ่อนจากจอโดยค่าเริ่ม (ปุ่ม Show Complete) แต่ยังอยู่ใน List เสมอ · ลำดับปกติ: Warning/Critical (คนแจ้ง) → In progress (คนแก้) → Waiting for review → Complete · หมุดเทา + เส้นประ = orphan (หา element เดิมไม่เจอ) ไม่ใช่ status เป็นแค่การแสดงผล

    4. Anchor + fallback

    ตอนปัก เก็บทั้ง 3 อย่างพร้อมกัน แล้วตอนแสดงผลลองตามลำดับ:

    #วิธีตอนปักตอนแสดง
    1figmaค่า data-figma ของ element ที่คลิก หรือ ancestor ที่ใกล้ที่สุดที่มี (+ dx,dy = จุดที่คลิกเป็นสัดส่วน 0–1 ในกรอบนั้น)หาใน section.screen[data-screen] นั้น ถ้าเจอ ตัวเดียว → วางหมุดที่กรอบ + dx,dy
    2selectorpath สั้นจาก screen root เช่น #s-store .store__grid > :nth-child(3) (ใช้ id / data-id / data-bind ก่อน nth-child)ใช้เมื่อ 1 ไม่เจอ หรือ data-figma ซ้ำกัน (ตอนนี้มีซ้ำ 6 ค่า เช่น 1:854 Shop button) หรือ element สร้างจาก JS ไม่มี data-figma
    3x,yจุดบน stage 1920×1080 (คิดกลับจาก scale ของ #stage)ใช้เสมอถ้า 1–2 ไม่เจอ · ถ้าเดิมผูก element ไว้แต่ตอนนี้หาไม่เจอ → หมุดเทา "orphan" + ปุ่ม Re-anchor ใน thread (ปักใหม่ ไม่เปลี่ยนข้อความ)
    • ถ้าคลิกแบบ Alt (จุดเปล่า) เก็บแค่ x,y → ไม่มีวัน orphan
    • element ถูกซ่อน (hidden, ขนาด 0, อยู่ใน tab อื่น) = ไม่โชว์หมุดบนจอ แต่ยังอยู่ใน List · ถ้ามี tab แล้วไม่ตรงกับ tab ปัจจุบันก็ซ่อนเหมือนกัน
    • tab / overlay: screen ที่มี tab หรือ dialog/modal เปิดอยู่ ให้แต่ละ screen ตอบเองผ่าน hook เล็ก ๆ MTX_SCREENS[key].commentCtx?.() → เช่น "tab:perk", "modal:buy" · ไม่มี hook = ไม่เก็บ tab
    • หมุดวาดในชั้นนอก stage (ไม่โดน scale) แล้วคำนวณตำแหน่งจาก getBoundingClientRect() · อัปเดตเมื่อ resize, เปลี่ยน screen, scroll ใน list (rAF ทุก 250 ms ตอนเปิด overlay)

    6. Storage

    แนะนำ: /api/comments บน Durable Object เดิมของ mtxworkingstation

    • prototype ถูกเสิร์ฟที่ /prototypes/controller-flow/ โดเมนเดียวกับ API → fetch ได้ตรง ๆ ไม่มี CORS, cookie ของ Access ติดไปเอง
    • ตัวตนจาก accessUser() ที่มีอยู่แล้ว (JWT Cf-Access-Jwt-Assertion, ต้องเป็น @squadxstudio.com) → server เขียน author เอง ปลอมไม่ได้ · ชื่อที่โชว์ใช้ส่วนหน้า @ (แบบ mtx-user.js)
    • เก็บใน DO Store ("mtx-team") ตารางใหม่ comments (1 แถว = 1 thread, JSON) + ตัวนับ crev แยกจาก rev ของ docs → poll comment ไม่ทำให้ wiki/tools ดึงข้อมูลใหม่ทั้งก้อน
    MethodPathทำอะไร

    POST/api/commentsbody = 1 op: create · reply · editMsg · deleteMsg · editTitle · status · reanchor · delete · restore → {ok, crev, thread} · server ตรวจสิทธิ์ต่อ op

    7. Sync + สิทธิ์

    ทำไมไม่ poll ตลอด

    • Cloudflare แพ็กเกจฟรี: Workers ได้ประมาณ 100,000 request / วัน รวมทั้งเว็บ (Durable Object ก็มีโควตารายวันแยก) · ต้องเช็กหน้า pricing ของ Cloudflare อีกครั้งก่อนสร้าง
    • poll ทุก 4 s = 900 request / ชม. / แท็บ · 10 คนเปิดทิ้ง 8 ชม. = 72,000 · และ QA Tracker ก็ poll ทุก 4 s อยู่แล้ว ใช้โควตาก้อนเดียวกัน → เสี่ยงหมด

    แนะนำ: Fetch ตามจังหวะ + ปุ่ม ↻ Fetch

    ดึงเมื่อหมายเหตุ
    เปิดหน้า prototype1 ครั้ง เพื่อได้เลขบนปุ่ม Comment
    สลับเข้าโหมด Comment1 ครั้ง
    กด ↻ Fetchข้างปุ่มบอก "updated 3 min ago"
    หลังส่ง / ตอบ / แก้ของตัวเองserver ตอบ thread ล่าสุดกลับมาในคำตอบเดียวกัน (ไม่ต้องยิงเพิ่ม)
    • GET ?since=crev ถ้าไม่มีอะไรใหม่ ได้ {unchanged:true} สั้น ๆ · เปลี่ยนหน้าไม่ต้องดึงใหม่ (ดึงทุกหน้าของ prototype มาครั้งเดียว แล้วกรองบนเครื่อง)
    • ประมาณการ: คนละ ~20–50 request / วัน → 10 คน ≈ 500 / วัน (< 1% ของโควตา)
    • Toast แจ้งคนอื่น: fetch แล้วเจอของใหม่ที่คนอื่นเขียน → toast มุมจอ เช่น "pim commented on Store · #12" (คลิก = กระโดดไปที่ thread) · ขึ้นทั้งโหมด Play และ Comment · ไม่ realtime จึงเพิ่ม เช็กเบา ๆ ทุก 3 นาที ตอนแท็บเปิดอยู่ (ไม่มีของใหม่ = คำตอบสั้น unchanged) ≈ 160 request / คน / วัน → 10 คน ≈ 1,600 (~1.6% ของโควตา) · ปรับ / ปิดได้ใน Dev Tools · อยากเห็นทันทีต้อง realtime (Phase 3)
    • ส่ง op แล้วจออัปเดตทันที (optimistic) · server ตอบ error → ถอยกลับ + toast · ดึงไม่สำเร็จ → ปุ่มขึ้น "offline"
    • ถ้าคนอื่นแก้ข้อความที่เรากำลังพิมพ์อยู่ → ไม่ทับช่องที่พิมพ์ ขึ้นแถบ "มีการแก้ใหม่"

    ถ้าอยาก realtime (ทีหลัง)

    • ใช้ WebSocket ไปที่ Durable Object แบบ Hibernation: เปิดเฉพาะตอนอยู่ในโหมด Comment, server ส่งเฉพาะตอนมีคนโพสต์ → ไม่มีการยิงซ้ำทุก 4 s · ตอนเงียบ DO หลับ ไม่กินเวลา
    • ใช้โควตาน้อยกว่า poll มาก แต่ต้องเขียนเพิ่มทั้ง worker + client และ Access ต้องผ่าน WebSocket ได้ → เก็บไว้ Phase 3 · API ฝั่ง client ออกแบบให้สลับจาก Fetch เป็น WebSocket ได้โดยไม่แก้ UI
    ทำอะไรใครทำได้ (ร่าง)
    ดู / สร้าง thread / replyทุกคนที่ login @squadxstudio.com
    แก้ / ลบ ข้อความเจ้าของข้อความเท่านั้น
    แก้ Title · Re-anchorคนเปิด thread + Admin
    เปลี่ยน Statusทุกคน (บันทึกว่าใครเปลี่ยนเป็น message ระบบ "nattaset → Complete")
    ลบ thread (soft) / กู้คืนคนเปิด thread + Admin
    Admin = รายชื่ออีเมลใน variable COMMENT_ADMINS ของ worker (ตั้งใน dashboard, keep_vars เปิดอยู่แล้ว)

    8. Backup

    • มี backup อัตโนมัติทุกวัน 03:00 (cron 0 20 * * *) เก็บ 30 ชุด แต่ backup() ตอนนี้เก็บแค่ตาราง docs → ต้องเพิ่มตาราง comments เข้าไปในก้อนเดียวกัน ({docs, comments}) และ restore ให้รู้จัก · แก้ไม่กี่บรรทัด
